Project Dependencies & Namespaces

This project utilizes standard .NET libraries alongside Entity Framework Core and PostgreSQL drivers to manage data persistence.

  • using System;
    Purpose: Contains fundamental and base classes in .NET.
    What it does: Provides core data types (like String, DateTime, Int32), console capabilities, and essential system utilities like exception handling.
  • using System.Collections.Generic;
    Purpose: Contains interfaces and classes that define generic collections.
    What it does: Allows you to create strongly-typed collections, such as List<T>, Dictionary<TKey, TValue>, and IEnumerable<T>, which are essential for managing groups of data without type-casting overhead.
  • using System.ComponentModel.DataAnnotations;
    Purpose: Provides attribute classes used to define metadata for your data models.
    What it does: Enables data validation and formatting directly on your properties. Common attributes include [Key] (to mark a primary key), [Required], and [StringLength].
  • using System.ComponentModel.DataAnnotations.Schema;
    Purpose: Provides attributes that denote database schema-specific configurations.
    What it does: Helps map your C# classes and properties to specific physical structures in the database. Common attributes include [Table("table_name")] and [Column("column_name")].
  • using System.Linq;
    Purpose: Contains classes and interfaces that support Language-Integrated Query (LINQ).
    What it does: Allows you to write declarative, readable queries directly in C# to filter, sort, and transform data from your database or memory collections.
  • using Microsoft.EntityFrameworkCore;
    Purpose: The primary namespace for Entity Framework Core (EF Core).
    What it does: Gives you access to the foundational ORM (Object-Relational Mapper) features, such as the DbContext class, tracking changes, managing migrations, and querying databases using LINQ.
  • using Npgsql;
    Purpose: The open-source .NET data provider for PostgreSQL.
    What it does: Acts as the bridge connecting your C# application to a PostgreSQL database instance, allowing EF Core to translate its commands into a language PostgreSQL understands.
